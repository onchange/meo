# MEO商談レポート — プロジェクト仕様書

## ツール名: 「MEOポテンシャル診断」

## このツールが解決する課題

山西屋の営業担当が、見込み客（店舗オーナー）に対して
「あなたのエリアでMEO対策がどれだけ効果的か」を
**政府統計データに基づいて1枚のレポートで示す**ための営業ツール。

### 社長のペインポイント（優先度順）

1. **新規営業で「あなたの店にMEO必要ですよ」と数字で説明できない**
2. **営業リストの優先順位を付けられない（どの店から攻めるべきかわからない）**
3. **既存クライアントへの継続提案（解約防止）のデータがない**

## 入力

```
都道府県（セレクト）
市区町村（セレクト、都道府県に連動）
業種（セレクト）
```

## 出力レポート（1ページ）

### ① MEOポテンシャルスコア（100点）

独自スコアをゲージチャートで大きく表示。レポートの最初に置き、営業インパクトを最大化する。

表示:
- 大きな数字で「**82点 / 100点**」
- ゲージチャート（SVG半円弧、色分け: 80+ 緑, 60-79 黄, 60未満 グレー）
- 効果ラベル:「MEO効果: 大」「MEO効果: 中」「MEO効果: 小」
- 一言コメント: 「競合密度が高く、昼間人口も豊富。MEO対策で差別化する効果が大きいエリアです」

#### スコア算出ロジック（詳細）

```
score = (競合密度スコア × 0.4) + (人口規模スコア × 0.3) + (昼間人口比スコア × 0.3)
```

各サブスコアは0〜100点に正規化する。

**競合密度スコア（重み: 40%）**

```
ratio = 当該市区町村の人口あたり事業所数 / 全国平均の人口あたり事業所数

競合密度スコア = min(100, ratio × 50)
```

- ratio = 1.0（全国平均と同じ）→ 50点
- ratio = 2.0（全国平均の2倍）→ 100点
- ratio >= 2.0 → 100点（上限キャップ）
- ratio < 1.0 → 50点未満

意味: 人口あたり同業者が多いほど、MEOで差別化する価値が高い。

**人口規模スコア（重み: 30%）**

```
人口規模スコア = min(100, 当該市区町村の人口 / 3000)
```

- 人口30万人以上 → 100点（上限キャップ）
- 人口15万人 → 50点
- 人口3万人 → 10点

意味: 商圏人口が多いほど、Google検索・マップ検索のボリュームが大きい。

**昼間人口比スコア（重み: 30%）**

```
昼間人口比スコア = min(100, 昼夜間人口比 × 50)
```

- 昼夜間人口比 = 1.0（昼夜同じ）→ 50点
- 昼夜間人口比 = 2.0（昼間が2倍）→ 100点
- 昼夜間人口比 >= 2.0 → 100点（上限キャップ）

意味: 通勤者が流入するエリアほど「近くの○○」でローカル検索されやすい。

**スコア別コメントテンプレート**

| スコア範囲 | ラベル | 色 | コメント |
|---|---|---|---|
| 80〜100 | MEO効果: 大 | 緑 | 競合密度が高く、昼間人口も豊富。MEO対策で差別化する効果が大きいエリアです。 |
| 60〜79 | MEO効果: 中 | 黄 | 一定の競合があり、MEO対策で上位表示を狙う価値があるエリアです。 |
| 0〜59 | MEO効果: 小 | グレー | 競合は比較的少ないですが、早期のMEO対策で先行者優位を確保できます。 |

### ② エリア競合密度

表示:
- 「大阪市中央区の歯科診療所は **142件**」
- 「大阪府平均の **3.2倍** / 全国平均の **4.8倍**」
- 横棒グラフ（Chart.js）: この市区町村 vs 府平均 vs 全国平均

データソース: e-Stat 経済センサス（令和3年）
  統計表ID: `0004005687`（産業(小分類)別事業所数 − 市区町村）

### ③ 人口あたり店舗密度

表示:
- 「人口1万人あたり歯科診療所 **13.2件**」
- 「全国平均: 5.3件」
- 密度が高いほど「競合が激しい → MEOで差別化しないと埋もれる」

データソース:
  - 事業所数: 上記②と同じ
  - 人口: e-Stat 国勢調査（令和2年）人口 − 市区町村

### ④ エリア人口プロフィール

表示:
- 総人口
- 昼夜間人口比
- 年齢構成ドーナツチャート（15歳未満 / 15-64歳 / 65歳以上の割合）

用途:
  - 昼間人口比が高い → 通勤者がランチや帰り道に「近くの○○」で検索
  - 高齢者比率が高い → マップ検索で病院・整骨院を探す傾向

データソース:
  - 総人口: e-Stat 国勢調査 統計表ID `0003433219`
  - 年齢3区分比率: e-Stat 国勢調査 統計表ID `0003445163`
  - 昼夜間人口比: e-Stat 国勢調査 統計表ID `0003454499`

### ⑤ エリアマップ

表示:
- Leaflet + OpenStreetMap による地図
- 市区町村中心座標にピンを配置（競合数に応じて最大80件を周辺に散布表示）
- 中心マーカー（青）+ 競合ピン（赤）で視覚的に密集度を表現
- サマリー: 「**3763件**の飲食店が札幌市中央区にあります（地図上には80件を表示）」

座標データ: piuccio/open-data-jp-municipalities（GitHub）から市区町村中心座標を取得

※ 将来的にはGoogle Places API等で実際の店舗位置をプロットする予定

### ⑥ 営業トーク用の一言サマリー

テンプレート:
- 「{市区町村名}は{業種}の競合が全国平均の{倍率}倍。Googleマップで検索されるお客様に見つけてもらうには、上位3位以内の表示が不可欠です。」
- コピーボタン付き（クリップボードにコピー）

## データ調達戦略

### 方針: 事前ダウンロード → JSONファイル化 → 静的サイトに同梱

**理由:**
- e-Stat APIはリアルタイム呼び出しにはレスポンスが遅い
- 経済センサスのデータは5年ごとの更新なので、リアルタイム性は不要
- 全国約1,740市区町村 × 主要業種（8業種）= 約14,000行のデータ
- JSON化すれば数MBに収まり、静的サイトに同梱可能

### 必要データと取得手順

#### Step 1: 経済センサス — 業種別事業所数

e-Stat API getStatsData で取得:
- 統計表ID: `0004005687`
- 令和3年経済センサス-活動調査 産業横断的集計

#### Step 2: 国勢調査 — 人口データ

e-Stat API で取得:
- 総人口: 統計表ID `0003433219`
- 年齢3区分比率: 統計表ID `0003445163`
- 昼夜間人口比: 統計表ID `0003454499`

#### Step 3: 全国平均・都道府県平均の事前計算

Node.jsスクリプトで全データを集約し、以下を事前計算:
- 全国の業種別 人口あたり事業所数（per 10,000人）
- 都道府県別の業種別 人口あたり事業所数
- 出力: `data/averages.json`

#### Step 4: 市区町村座標の付与

piuccio/open-data-jp-municipalities から中心座標を取得し municipalities.json にマージ

### 業種コード対応表（e-Stat内部コード）

| 表示名 | e-Statコード |
|---|---|
| 歯科診療所 | 833 |
| 一般診療所（内科等） | 832 |
| 美容業（美容院） | 783 |
| 理容業 | 782 |
| 飲食店 | 76 |
| 療術業（整骨院・鍼灸院等） | 835 |
| 学習塾 | 823 |
| 不動産代理業・仲介業 | 682 |

#### 最終成果物

```
data/
├── municipalities.json    # 市区町村コード → 名前・座標のマッピング（~265KB）
├── census_businesses.json # 市区町村 × 業種 → 事業所数（~252KB）
├── census_population.json # 市区町村 → 人口データ（~318KB）
└── averages.json          # 全国平均・都道府県平均（~47KB）
```

合計: ~880KB（gzip後 ~150KB）

## 注意事項

- e-Stat APIのレート制限あり（スクリプトは1秒間隔 + 3回リトライで対応済み）
- 産業分類コードはe-Stat内部コードを使用（標準産業分類の番号とは異なる）
- 市区町村座標は中心点の近似値（8件の未マッチ市区町村あり）
- 地図上の競合ピンは統計データに基づく散布表示であり、実際の店舗位置ではない
